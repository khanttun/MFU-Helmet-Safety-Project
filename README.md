# MFU Helmet Safety Entry System

A computer-vision gate control system that detects whether a rider is wearing a helmet, publishes the result over MQTT, and controls an automated barrier using an ESP32. The project connects a camera feed, YOLO-based object detection, a Node-RED dashboard, and a physical servo barrier into one monitoring workflow.

## Project overview

Pipeline:

Camera -> Python/OpenCV -> YOLO model -> MQTT (HiveMQ) -> Node-RED -> MQTT -> ESP32 -> servo barrier

This repository contains the Python detector, simulation scripts, a ready-to-import Node-RED flow, and the ESP32 firmware for the gate controller.

## Features

- Live helmet/no-helmet detection using YOLOv11 model weights
- MQTT event publishing for `SAFE`, `VIOLATION`, and `NONE` states
- Debounced classification to avoid noisy toggling from a single frame
- Saved violation snapshots for review
- Local MJPEG video stream for dashboard preview
- Node-RED dashboard and SQLite logging
- ESP32-based barrier control via MQTT command topic

## MQTT topics

The default topic prefix is `mfu-helmet-6731502018`. If you want your own deployment, change it consistently in Python, Node-RED, and ESP32.

| Topic | Direction | Payload |
|---|---|---|
| `<prefix>/event` | Python -> Node-RED | JSON such as `{"status":"SAFE","confidence":0.93,"timestamp":"...","camera_id":"gate-1","image":"violations/violation_...jpg"}` |
| `<prefix>/cmd` | Node-RED -> ESP32 | `OPEN` or `CLOSE` |
| `<prefix>/status` | ESP32 -> Node-RED | `OPEN`, `CLOSED`, or `OFFLINE` |

## Quick start

### 1) Install dependencies

```bash
pip install -r requirements.txt
```

### 2) Configure the broker

The project is configured to use the public HiveMQ broker by default:

- Host: `broker.hivemq.com`
- Port: `1883`
- Topic prefix: `mfu-helmet-6731502018`

You can override this with environment variables when running the detector or simulator:

```bash
set MQTT_HOST=broker.hivemq.com
set MQTT_PORT=1883
set TOPIC_PREFIX=mfu-helmet-6731502018
```

For HiveMQ Cloud or secure communication, enable TLS and set:

- `MQTT_TLS=1`
- `MQTT_USER`
- `MQTT_PASS`
- `MQTT_PORT=8883`

### 3) Import the Node-RED flow

In Node-RED:

1. Click the menu and choose `Import`
2. Select `nodered_flow.json`
3. Deploy the flow
4. Open the dashboard at `http://localhost:1880/ui`

The flow listens to `<prefix>/event`, sends commands to `<prefix>/cmd`, and listens for barrier status on `<prefix>/status`.

### 4) Configure the ESP32 firmware

Edit the Wi-Fi and MQTT settings in `esp32_barrier/esp32_barrier.ino` before uploading:

- `WIFI_SSID`
- `WIFI_PASS`
- `MQTT_HOST`
- `MQTT_PORT`
- `USE_TLS`
- `MQTT_USER`
- `MQTT_PASS`
- `TOPIC_PREFIX`

Recommended wiring:

- Servo signal -> GPIO 18
- Servo power -> 5V/VIN
- Servo ground -> common ground with the ESP32

If the servo causes resets, use a separate 5V power source for the servo and share the ground.

### 5) Run the detection script

```bash
python helmet_detect.py
```

Environment variables you may tune:

- `MODEL_PATH` (default `best.pt`)
- `CAM_INDEX` (default `0`)
- `CONF_THRES` (default `0.30`)
- `CONFIRM_FRAMES` (default `3`)
- `SHOW_WINDOW` (`1` or `0`)
- `STREAM` (`1` or `0`)
- `STREAM_PORT` (default `5000`)

The detector checks for `helmet` and `no_helmet` class names, debounces repeated states, saves a snapshot on violation detection, and publishes an event payload to the broker.

### 6) Test without a camera

Use the simulator to validate the rest of the system before using a real camera:

```bash
python simulate_event.py SAFE
python simulate_event.py VIOLATION
```

These commands publish test payloads to `<prefix>/event` and should cause the Node-RED dashboard and barrier controller to respond accordingly.

## Training a custom model

The project follows a standard YOLO custom dataset workflow.

1. Collect 300-500 photos with helmet on and off under different lighting, angles, and backgrounds.
2. Prepare the image folders and labels in a YOLO layout.
3. Use `labelImg` to annotate images with the classes `helmet` and `no_helmet`.
4. Run the validation split script:

```bash
python split_dataset.py
```

5. Train the model:

```bash
python train_model.py
```

The training script expects a model file such as `yolo11n.pt` and a dataset configuration like `dataset.yaml`.

## Privacy and operational notes

- Violation snapshots can contain identifiable faces; keep them in a secure location.
- Keep the camera fixed and well-lit for more stable detection.
- The default topic prefix should stay unique to prevent collisions with other MQTT users.
- Do not commit Wi-Fi or broker credentials to version control.

## Troubleshooting

- No camera detected: try a different `CAM_INDEX` value such as `0`, `1`, or `2`.
- MQTT not reaching Node-RED: confirm the topic prefix matches exactly across Python, Node-RED, and ESP32.
- ESP32 connection errors: check Wi-Fi SSID/password and whether TLS is enabled on the broker.
- Servo jitter or resets: power the servo from a dedicated 5V source and share the ground.
- Model confusion: verify the class order in `dataset.yaml` matches the training labels.
- Dashboard not updating: confirm the Node-RED SQLite node path is writable and the broker is connected.

## Demo summary

This system is designed for a smart entry gate demo: the detector analyzes each rider, marks a violation if no helmet is detected, sends an MQTT event, updates the dashboard, and commands the barrier to remain closed until the state is resolved.
